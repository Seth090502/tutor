### Headline findings (read these first)

1. **No tool in this cluster handles the target corpus well.** Game engines need C/C++ with heavy macros, C#, Rust, Lua/GDScript, HLSL/GLSL and CMake. Coverage of that set:
   - code-index-mcp has no C, C++ or Lua symbol extraction at all (they route to a fallback that emits zero symbols; see section 5).
   - aider has tag queries for c, cpp, c_sharp, rust, lua but none for hlsl, glsl, cmake or gdscript (listing of `aider/aider/queries/*`).
   - Only codanna (Rust: C, C++, C#, Lua, GDScript, Rust parsers in `src/parsing/*`) and code-graph-rag (libclang hybrid for C/C++) go beyond plain tree-sitter for any of these, and neither expands Unreal-style macros such as `UCLASS`/`UFUNCTION` (grep for these strings in codanna `src` returned nothing; cgr relies on libclang plus a recovery pass).
   - Nobody indexes shaders or CMake as first-class languages except codebase-memory-mcp (lists GLSL, HLSL, CMake, GDScript among 162 grammars, "not yet benchmarked").
2. **Independent evidence says generated repository overviews do not help agents.** The study "Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?" (arXiv 2602.11988; Gloaguen, Mündler-Sasahara, Müller, Raychev, Vechev) reports that context files "do not generally improve task success rates, while increasing inference cost by over 20% on average", and that "repository overviews ... are not helpful", for both LLM-generated and developer-written files. I fetched the abstract; I did not read the full paper. This argues for on-demand navigation tools over pre-generated DeepWiki-style prose. No repository in this cluster (deepwiki-open, RepoAgent) provides any measurement that its generated documentation helps an agent.
3. **Token-saving claims are all vendor-authored and mostly compare against weak baselines.** See section 17.
4. **Name-based directory exclusion silently deletes game source.** code-index-mcp, deepwiki-open, repomix and codebase-memory-mcp exclude by directory name (`bin`, `build`, `out`, `obj`, `docs`, `external`, `third_party`, `tools`, `scripts`, `generated`, `vendor`, ...). Details in section 16.

## 1. Aider (repomap.py)

- What it is: terminal AI pair programmer; the repo map is the single most-copied idea in this cluster. Apache-2.0. Python. Mature (version 0.86.3.dev in `aider/__init__.py:3`).
- Ingestion: file set comes from git, not a directory walk. `aider/repo.py:433-470` (`get_tracked_files`) lists blobs of the HEAD commit tree (plus staged files later in the function), so `.gitignore` is honoured implicitly because ignored files are never tracked. `.aiderignore` is handled in `aider/coders/base_coder.py:501-539`. Language by extension through `grep_ast.filename_to_lang` (`repomap.py:280`). Files that fail `Path.is_file()` are skipped with a one-time warning (`repomap.py:406-418`). No binary or size detection in the map path (files without a tag query simply yield no tags). No vendored/generated detection.
- Indexing:
  - Symbol extraction by tree-sitter `*-tags.scm` queries (`aider/queries/tree-sitter-language-pack/*.scm`, 2,047 lines total; `tree-sitter-languages/` is the older set). Captures named `name.definition.*` become `def`, `name.reference.*` become `ref` (`repomap.py:304-336`).
  - Reference backfill: when a language query yields definitions but no references (C++ is the stated example in the code comment; `cpp-tags.scm` is 15 lines, definitions only), every `Token.Name` token from a Pygments lexer is emitted as a `ref` with `line=-1` (`repomap.py:338-363`). This is a cheap, language-agnostic approximation of a reference graph, and it is the reason aider's map works on C++ at all.
  - Cache: `diskcache` SQLite keyed by file path with mtime, one directory `.aider.tags.cache.vN` in the repo (`repomap.py:35-43, 233-264`). Incremental by mtime only. No file watching; the map is recomputed per request unless the refresh policy (`auto` | `always` | `files` | `manual`, `args.py:254-261`) returns a cached copy; `auto` caches only when the last map took more than 1.0 s (`repomap.py:592-613`).
  - No embeddings, no trigram index, no full-text index.
- Ranking (`repomap.py:365-574`): builds a NetworkX `MultiDiGraph` with file nodes and one edge per (referencer, definer, identifier). Edge weight = `mul * sqrt(num_refs)` (`repomap.py:512`) where `mul` starts at 1 and is x10 if the identifier is mentioned in the user message, x10 if snake/kebab/camel case and at least 8 characters, x0.1 if it starts with `_`, x0.1 if defined in more than 5 files (`repomap.py:487-499`), and x50 when the referencer is a file already in the chat (`repomap.py:507-509`). Personalisation vector (`100/len(fnames)` per file) is applied to chat files, files named in the message, and files whose path components match mentioned identifiers (`repomap.py:422-445`). PageRank via `nx.pagerank(G, weight="weight", personalization, dangling)` (`repomap.py:519-531`); each node's rank is then distributed over its out-edges to rank (file, identifier) definitions (`repomap.py:533-545`). Files in the chat are removed from the output (`repomap.py:556`). Special root files (README, package manifests; `aider/special.py`) are prepended (`repomap.py:657-662`).
- Token budgeting (the part most worth copying): the output is a binary search over the number of ranked tags. Start at `max_map_tokens // 25` tags (`repomap.py:676`), render, count tokens, accept the first result within 15 percent of the budget or the best under it (`repomap.py:677-703`). Token counting for texts over 200 characters is estimated by sampling every Nth line and scaling (`repomap.py:89-101`). Rendering uses `grep_ast.TreeContext` to print only the lines of interest with their parent scopes, and truncates every line to 100 characters (`repomap.py:710-784`). Default budget 1,024 tokens (`--map-tokens`), multiplied when no files are in the chat (`--map-multiplier-no-files`, default 2 in `args.py:263-268`, while the class default is 8 at `repomap.py:56`: a discrepancy to be aware of). Falls back to a global map if chat files are disjoint from the rest (`base_coder.py:726-748`).
- What it exposes to agents: nothing over MCP. The map is injected as a user message with the prefix "Here are summaries of some files present in my git repository. Do not propose changes to these files, treat them as *read-only*." (`aider/coders/base_prompts.py:45-48`). Output shape: file path, then elided code lines (`⋮...`) with the definition lines and their parent scope headers.
- Scale/perf evidence: aider's own docs (`aider/website/docs/repomap.md`, `_posts/2023-10-22-repomap.md`) describe the design; the repo-wide SWE-bench Lite post (`_posts/2024-05-22-swe-bench-lite.md`) does not isolate the repo map's contribution. There is a one-time "initial scan can be slow" warning above 100 uncached files (`repomap.py:391-395`). No independent measurement found.
- Ideas to adopt (Rust):
  1. Budget-fitted map by binary search over ranked definitions, with sampled token estimation. Effort S. Crates: `tiktoken-rs` or the embedding model's `tokenizers` for counting. Port the idea (Apache-2.0, clean-room).
  2. Query-conditioned personalised PageRank over a file-to-file graph with the weight rules above (sqrt dampening, long-identifier boost, generic-name penalty, query-mention boost). Effort M. Crate: `petgraph` plus about 40 lines of power iteration, or `pagerank-rs`. The vault can improve on aider by using real definition-to-use edges (section 6) and by computing PageRank once at index time, personalising at query time.
  3. Pygments-style ref backfill: for languages whose tag queries produce no references, emit every identifier-like token as a weak reference. In Rust this is a tree-sitter `identifier`/`type_identifier` walk or a tokenizer pass. Effort S. This is directly useful for macro-heavy C++ where call-site parsing fails.
  4. Elided-scope rendering (show only lines of interest plus enclosing scope headers). Effort M. Port of `grep_ast` TreeContext logic using tree-sitter.
  5. The `.scm` tag queries are reusable with attribution (they are adapted from upstream grammar repos, see `queries/tree-sitter-language-pack/README.md`, which points to per-repo licences, so check each one).
- Caveats: PageRank over names is name-based, not resolution-based; common names are hammered by the 0.1 penalty rather than resolved. The map is a navigation aid for one edit session, not a retrieval index.
- Fit: port_ideas.

## 2. Repomix

- What: packs a repository into one XML/Markdown/JSON/plain file for an LLM. MIT. TypeScript, mature (v1.18.1). Also ships an MCP server and a Claude "skills" generator.
- Ingestion: `globby` glob walk (`src/core/file/fileSearch.ts`) honouring `.gitignore`, `.ignore`, `.repomixignore` (`fileSearch.ts:22`, config `ignore.useGitignore/useDotIgnore` at `src/config/configSchema.ts:159-161`); a default ignore list (`src/config/defaultIgnore.ts`, 163 lines) that includes `vendor/**`, `target/**`, `logs/**` and similar; git worktree reference handling (`fileSearch.ts:46-58`). Binary detection by extension (`is-binary-path`) then by content (`isbinaryfile`), with UTF-16/BOM exemptions (`src/core/file/fileRead.ts:2-3, 20, 72-75`). Max file size default 50 MB (`configSchema.ts:125`). Secrets: `secretlint` core and recommended preset (`package.json:85-86`) run in worker batches of 50 files (`src/core/security/securityCheck.ts:19-30`) over files and optionally git diff/log. Files are optionally sorted by git change frequency (`output.git.sortByChanges`, default on, last 100 commits; `configSchema.ts:150-152`).
- Indexing: none. It is a packer. The only analysis is the optional `--compress` mode: web-tree-sitter (WASM) extracts signatures and drops bodies, joining chunks with the separator `⋮----` (`src/core/treeSitter/parseFile.ts:30`; rationale for WASM at `parseFile.ts:3-17`). Per-language queries live in `src/core/treeSitter/queries/` (C, C++, C#, CSS, Dart, Go, Java, JavaScript, PHP, Python, Ruby, Rust, Solidity, Swift, TypeScript, Vue; no Lua, GLSL, HLSL, CMake, GDScript). `queryCpp.ts` is byte-for-byte the same capture set as aider's `cpp-tags.scm` plus a `(comment)` capture, which shows how much this field copies from one origin. Compression is best-effort and never throws, so a bad file falls back to uncompressed (`parseFile.ts:33-41`).
- Ranking: none. Sorting is by path or by git change count. A token tree (`--token-count-tree`) shows which directories cost the most (README near line 898).
- Exposed to agents: MCP server `repomix-mcp-server` (`src/mcp/mcpServer.ts`), tools: `pack_codebase` (input `directory`, `compress`, `includePatterns`, `ignorePatterns`, `topFilesLength` default 10, `style` xml|markdown|json|plain; output `outputId`, `outputFilePath`, `totalFiles`, `totalTokens`, `directoryStructure`; `packCodebaseTool.ts:41-84`), `pack_remote_repository`, `read_repomix_output` (`outputId`, `startLine`, `endLine`; returns `content`, `totalLines`, `linesRead`; `readRepomixOutputTool.ts:20-40`), `grep_repomix_output` (pattern, `contextLines`, `beforeLines`, `afterLines`, `ignoreCase`; returns `matches[{lineNumber,line,matchedText}]`, `formattedOutput`, `totalMatches`; `grepRepomixOutputTool.ts:20-60`), `file_system_read_file`, `file_system_read_directory` (sandbox mode only), `generate_skill`, `attach_packed_output` (`mcpServer.ts:64-80`). Budgeting: the pack tool's own description says compression "generally not needed since grep_repomix_output allows incremental content retrieval" (`packCodebaseTool.ts:43-48`), so the intended pattern is pack once, then grep and range-read the output. `--token-budget <n>` fails with a non-zero exit when the output exceeds n tokens (README line 680). A `--skill-generate` mode writes a `.claude/skills/<name>/` directory from a repo (README lines 1216-1237).
- Scale evidence: README states compress "reduces token count" and cites about 70 percent in the tool description (`packCodebaseTool.ts:46`), vendor claim, no measurement attached. Worker batching exists for security and metrics (`securityCheck.ts:19-30`), which implies it is built for large file counts, but I found no published timing.
- Ideas to adopt: (a) the "pack once, grep and range-read the artifact by id" tool shape is exactly what a vault exposes natively, so the vault does not need a pack step; (b) per-directory token tree so an agent can see where the cost sits before reading (effort S; the vault can attach token counts per document and per directory at index time); (c) skill generation: emit a short per-repo "how to navigate this vault repo" skill file from the repository document (effort S); (d) secretlint-style scanning of content before it is indexed, with the vault using the `gitleaks` ruleset or a Rust port, not secretlint (Node). Effort M.
- Fit: port_ideas (d and b), reference_only otherwise.

## 3. gitingest

- What: web and CLI tool producing a text digest (summary, tree, concatenated contents) from a GitHub URL or local directory. MIT. Python, version 0.3.1. Contains no MCP server at HEAD (case-insensitive grep for "mcp" over `*.py`, `*.toml`, `*.md` returned nothing).
- Ingestion: recursive walk in `src/gitingest/ingestion.py` with hard limits `MAX_FILE_SIZE` 10 MB, `MAX_DIRECTORY_DEPTH` 20, `MAX_FILES` 10,000, `MAX_TOTAL_SIZE_BYTES` 500 MB (`src/gitingest/config.py:6-9`, enforced at `ingestion.py:234-320`). Default ignore patterns are a set in `src/gitingest/utils/ignore_patterns.py:7-` (language caches, lock files, `node_modules`, and so on). `.gitignore` and `.gitingestignore` are applied unless `include_gitignored=True` (`entrypoint.py:262-275`). Symlinks are handled explicitly (`ingestion.py:187`). Text decoding probes a list of encodings (`src/gitingest/utils/file_utils.py:20-33`). Notebook conversion exists (`utils/notebook.py`).
- Indexing, ranking: none.
- Exposed: library function plus HTTP API and CLI. Output is a three-part tuple `(summary, tree, content)` (`output_formatter.py:25-60`). Budgeting is only an informational "Estimated tokens" string from `tiktoken` `o200k_base` (`output_formatter.py:181-197`).
- Scale evidence: only the hard caps above. No benchmark.
- Ideas: the hard-cap set (files, size, depth) as a first line of safety against runaway ingestion; the 10 MB per-file cap is too low for generated engine sources and should be a per-class policy in the vault. Effort S.
- Fit: reference_only.

## 4. claude-context (Zilliz)

- What: MCP server that gives coding agents semantic code search backed by a vector database. MIT. TypeScript monorepo (packages `core`, `mcp`, `vscode-extension`, `chrome-extension`). Active.
- Ingestion: extension allow-list (`packages/core/src/context.ts:56-65`: `.ts .tsx .js .jsx .py .java .cpp .c .h .hpp .cs .go .rs .php .rb .swift .kt .scala .m .mm .dart .sol .md .markdown .ipynb`; no `.lua`, `.gd`, `.hlsl`, `.glsl`, `.cmake`, `.inl`, `.cc`, `.cxx`) and glob ignore patterns (`context.ts:67-100+`: `node_modules/**`, `dist/**`, `build/**`, `out/**`, `target/**`, `.git/**`, `logs/**`, `tmp/**`, `.env`, and so on). `IgnoreMatcher` in `utils/ignore-matcher.ts`. Chunk cap 450,000 per codebase (`context.ts:860`), after which indexing stops with a warning.
- Indexing:
  - Chunking: `AstCodeSplitter` (tree-sitter native bindings) with chunk size 2,500 characters and overlap 300 (`splitter/ast-splitter.ts:29-30`). It extracts nodes whose types are in a per-language allow-list (`ast-splitter.ts:16-26`; for C++ it uses `function_definition`, `class_specifier`, `namespace_definition`, `declaration`, and C is mapped onto the C++ grammar at line 97), walks the whole tree (so nested nodes yield overlapping chunks), splits oversized chunks by lines, and adds overlap by prepending the last 300 characters of the previous chunk (`ast-splitter.ts:228-254`; the line-number adjustment is approximate). Languages without a grammar mapping (Lua, GDScript, shaders, CMake, Go-adjacent, and others) fall back to a LangChain character splitter (`ast-splitter.ts:44-50`). It does not handle macro-wrapped declarations.
  - Embeddings: pluggable (OpenAI default `text-embedding-3-small`, VoyageAI `voyage-code-3`, Gemini, Ollama; `packages/mcp/src/config.ts:88-98`). Batch size 100 (`context.ts:859`). Vector store is Milvus or Zilliz Cloud (`vectordb/`).
  - Hybrid search: when `HYBRID_MODE` is on, the collection stores dense vectors plus BM25 sparse vectors and queries both, merging with RRF (`context.ts:279-305, 531-623`). Dense-only otherwise.
  - Incremental: per-codebase Merkle DAG plus per-file SHA-256 snapshot stored in `~/.context/merkle/<md5(path)>.json` (`sync/synchronizer.ts:16-34`, `sync/merkle.ts`). The MCP server polls every 5 minutes (`packages/mcp/src/sync.ts:10`) and also watches a trigger file (`sync.ts:276-277`).
- Ranking: vector similarity (plus BM25 in hybrid, merged by RRF). No symbol boosts, no graph, no recency.
- Exposed to agents (`packages/mcp/src/index.ts:125-219`): `index_codebase(path, force, splitter ast|langchain, customExtensions, ignorePatterns)`, `search_code(path, query, limit default 10 max 50, extensionFilter)`, `clear_index(path)`, `get_indexing_status(path)`. Result shape: text, one block per hit with `Location: relativePath:startLine-endLine` and content truncated to 5,000 characters (`handlers.ts:802-812`). Indexing runs in the background with per-path de-duplication (`handlers.ts:16-19, 387, 487`). Requires absolute paths. There is no "read file", "outline", "definition" or "references" tool; the agent still uses its own Read and Grep.
- Scale/perf evidence (vendor-authored): `evaluation/README.md:20-30` reports 30 SWE-bench-Verified instances (filtered to 2-file modifications), GPT-4o-mini, 3 runs per condition: F1 0.40 vs 0.40, tokens 73,373 vs 44,449 (-39.4 percent), tool calls 8.3 vs 5.3. It measures file-localisation retrieval, not task success. Small sample, weak model, baseline of grep-only.
- Ideas to adopt: (a) Merkle/hash snapshot for cheap multi-repo change detection (effort S; the vault should use git tree hashes or blake3 per file, no Merkle needed); (b) hybrid dense plus lexical with RRF is what the vault already plans; (c) the explicit `get_indexing_status` tool plus background indexing, so a tool call never blocks past the client deadline (effort S). Reject: Milvus dependency, cloud embeddings by default, 2,500-character chunks that ignore macros.
- Fit: port_ideas (c, a), reject as dependency.

## 5. code-index-mcp (johnhuang316)

- What: Python MCP server with a file index, ripgrep-family search and tree-sitter symbol extraction for a handful of languages. MIT. Version 2.17.1. Small (about 13.7k lines of Python).
- Ingestion: `pathspec` plus a hard-coded filter (`src/code_index_mcp/constants.py`): supported-extension list of about 100 entries including all C/C++ extensions and `.lua`, and excluded directory names including `build`, `out`, `bin`, `obj`, `dist`, `target`, `vendor` (`constants.py:~83-110`). Name-based exclusion of `bin`/`obj`/`build`/`out` is lossy for engines.
- Indexing: tiered. A "shallow" index is a file list; a "deep" index extracts symbols into SQLite (`indexing/sqlite_store.py:99-142`: tables `files(path, language, line_count, imports, exports, package, docstring)` and `symbols(symbol_id, file_id, type, line, end_line, signature, docstring, called_by, short_name)`, indexed on file and short name). Specialised strategies exist only for Python, JavaScript, TypeScript, Java, Kotlin, C#, Go, Rust, Zig, Objective-C (`indexing/strategies/`). Everything else, including `.c`, `.cpp`, `.h`, `.hpp`, `.lua`, goes to `FallbackParsingStrategy` (`strategy_factory.py:76-90, 182-184`), whose `parse_file` returns line count and an empty symbol set (`fallback_strategy.py:23-40`). Net result: no symbols for C, C++, Lua, GLSL or HLSL. `called_by` is a flat list built in `json_index_builder.py:311`. File watching via `watchdog` with per-OS observer selection and a rebuild on change (`services/file_watcher_service.py`).
- Ranking: none. Search delegates to ugrep, ripgrep, ag or grep, auto-selected (`search/*.py`).
- Exposed (`src/code_index_mcp/server.py:343-530`): `set_project_path`, `search_code_advanced(pattern, case_sensitive, context_lines, file_pattern, fuzzy, regex, start_index, max_results=10)` with pagination, `find_files(pattern)`, `get_file_summary(file_path)` (line count, functions/classes, imports, complexity), `get_symbol_body(file_path, symbol_name)` returning `type`, `line`, `end_line`, `code`, `signature`, `docstring`, `called_by`, `refresh_index`, `build_deep_index(max_workers, timeout)`, `get_settings_info`, plus temp-directory and watcher tools. A stateful `set_project_path` call is required first, and about 14 tools are exposed.
- Evidence: none beyond README claims.
- Lessons: (a) a single-project, stateful `set_project_path` design is the opposite of what a multi-repo vault needs; (b) `get_symbol_body` (give a symbol name, get exactly its source plus its callers) is a good tool shape and is the cheapest way to cut reads; (c) shallow versus deep index tiers let a first query answer before the deep pass finishes; (d) silent fallback to "no symbols" with no per-file warning is the failure mode to avoid: the vault must report per-language coverage in `vault_info`.
- Fit: reference_only.

## 6. codanna (bartolli) - closest architectural twin

- What: "Local code intelligence MCP server and CLI for AI coding agents". Rust 2024 edition, Apache-2.0, version 0.16.0 (`Cargo.toml`). Uses `tantivy 0.26`, `tree-sitter 0.26`, `rmcp 3.1` (MCP), `ignore`, `notify`, `rayon`, `fastembed 5.6.0` (pinned; comment at `Cargo.toml` explains an `ort`/glibc issue), `memmap2`, `sha2`, `dashmap`. 745 stars; still small and single-author.
- Ingestion: `ignore::WalkBuilder` with gitignore chain, global gitignore, git exclude, a custom `.codannaignore`, no symlink following, `require_git(false)`, hidden files included (`src/indexing/walker.rs:29-45`). - Ideas to adopt: (a) the two-step handle pattern, resolve a fuzzy name to a stable id, then query by id, with an explicit "stop after N calls" rule in the description; (b) version-qualified ids (`/org/project/version`), which map to the owner's use case of several engine versions as separate vault repositories; (c) per-source owner configuration file committed in the source tree (`context7.json`) to scope what gets indexed: the vault can read an optional `.vaultignore` or `vault.toml` in each source tree. Effort S.
- Relation to the vault's books and papers: Context7 is the closest model for the "documentation" side of the vault, not for code navigation.
- Fit: reference_only.

## 14. Addition 1: codebase-memory-mcp (DeusData) - closest competitor to beat

- What: "code intelligence MCP server": a single native C executable that indexes a repository into a persistent SQLite graph. MIT. Created 2026-02-24, 45.5k stars as of 2026-10-01 (the growth rate is unusual; treat star counts as unverified signals), last commit 2026-09-30. The clone is about 1.4 GB on disk because grammars are vendored (`vendored/`, 158-162 tree-sitter grammars); GitHub API size is 291 MB.
- Security note for the owner: the installer "auto-detects installed coding agents and configures their documented MCP entries plus durable instructions, skills, and lifecycle hooks" (README "Quick Start") and ships a per-account coordination daemon. Do not install it on this machine without review; this study did not run it.
- Ingestion: layered ignores, hard-coded patterns then `.gitignore` hierarchy then `.cbmignore`; symlinks always skipped (README "Ignoring Files"; `src/discover/discover.c`, `gitignore.c`). A `fast` mode additionally skips directory names `generated gen fixtures testdata docs doc examples samples assets static public media third_party thirdparty 3rdparty external migrations scripts tools bin build out` and many suffixes (`discover.c:~56-125`), which would drop real code in engine trees. Resource limits and file-size caps are documented in `docs/INDEX_RESOURCE_LIMITS.md` (not read).
- Indexing: tree-sitter (162 grammars including GLSL, HLSL, CMake, GDScript, Lua per README "Also supported" list) then ordered pipeline passes (`src/pipeline/pass_*.c`: definitions, calls, usages, imports, tests, complexity, infra, git history, similarity, semantic, importance, cross-repo, route nodes, compile commands). "Hybrid LSP" is a hand-written C type-resolution layer for Python, TS/JS, PHP, C#, Go, C, C++, Java, Kotlin, Rust, Perl (README "Hybrid LSP"; C/C++ side "handles macros + typedef chains + header-vs-source linking; C++ templates, namespaces, auto inference, method resolution via class hierarchy"). `pass_compile_commands.c` reads compile databases. Louvain community detection for clusters; MinHash plus LSH for near-clone `SIMILAR_TO` edges (`src/simhash/minhash.c`); semantic search with bundled `nomic-embed-code` embeddings (768 dimensions int8) and an 11-signal score (README "Search"). BM25 uses SQLite FTS5 with a camelCase/snake_case tokenizer `cbm_camel_split`.
- Ranking: `pass_importance.c` computes weighted degree "Aider-repomap shaped": `sqrt(num_refs) * priv(0.1) * generic(0.1 if defined in 5 or more files) * distinct(10 if snake/camel and length 8 or more) * test_penalty(0.1)`. The header explicitly says PageRank is deliberately not built until it "earns itself against a fixed judgment set".
- Incremental: a watcher polls git (HEAD movement or dirty tree) with adaptive intervals of 5 s plus 1 s per 500 files, capped at 60 s (`src/watcher/watcher.h`); only a successful reindex commits the watcher baselines, so skipped or failed ones retry rather than get lost. Index artifact `.codebase-memory/graph.db.zst` (SQLite, indexes stripped, `VACUUM INTO`, zstd, 8-13:1) can be committed so teammates skip the first index; the README warns one team reached about 6 GB of history by committing every rewrite.
- Exposed (README "MCP Tools", 17 tools): `index_repository(repo_path, async, status, persistence)` (async job plus status polling is documented because clients time out), `list_projects`, `delete_project`, `index_status`, `check_index_coverage` ("a clean result means no recorded gap, not proof of completeness"), `search_graph` (structural, BM25 and semantic; `offset`/`limit` and `semantic_offset`/`semantic_limit`), `trace_path` (BFS depth 1-5, direction), `detect_changes` (git diff to affected symbols with risk), `query_graph` (read-only openCypher subset that fails loudly on unsupported syntax), `get_graph_schema` ("Run this first"), `compare_graphs`, `get_code_snippet` (by qualified name), `get_file_outline`, `get_architecture`, `search_code` (graph-augmented grep over indexed files), `manage_adr`, `ingest_traces`.
- Output budgeting: `src/mcp/compact_out.c/.h` emits a compact table format ("tabular fields declared once in a header, rows streamed line by line") to cut repeated-key overhead for LLM consumers. jcodemunch has the same idea (MUNCH encoding, about 45 percent smaller than JSON by its own measurement).
- Evidence: (1) README "Performance" (vendor, Apple M3 Pro): Linux kernel 28M LOC, 75k files indexed in 3 minutes (4.81M nodes, 7.72M edges), Django about 6 s, Cypher under 1 ms. (2) Preprint arXiv 2603.27277, "Codebase-Memory: Tree-Sitter-Based Knowledge Graphs for LLM Code Exploration via MCP" (authors Vogel, Meyer-Eschenbach, Kohler, Grünewald, Balzer). I fetched the abstract only: 31 repositories, 83 percent answer quality versus 92 percent for a file-exploration baseline, 10x fewer tokens, 2.1x fewer tool calls. That is a quality drop of 9 points bought with the token saving, and it comes from the author group's own harness; whether authors overlap with the repository owner is unverified. (3) README claim "~3,400 tokens vs ~412,000" for five structural queries, labelled a 99.2 percent reduction. (4) The language benchmark (`docs/BENCHMARK.md`) grades 12 smoke questions per language (list functions, get a snippet, trace calls) as PASS/PARTIAL/FAIL against real repos (for example nlohmann/json 12/12), so it measures "does the tool return something plausible", not retrieval accuracy against ground truth.
- Ideas to adopt: async index job plus status; `check_index_coverage` honesty about gaps; compact tabular output; `get_architecture` single-call overview (languages, packages, hotspots, clusters); git-diff impact mapping (`detect_changes`); the importance formula; the team-shared artifact (the vault is a central server so this matters less).
- What the vault must not copy: a daemon that rewrites agent configuration; fast-mode directory-name skipping; a custom C type-resolver whose behaviour on Unreal-scale macros is unmeasured.
- Fit: port_ideas; also the benchmark competitor to compare against on the owner's actual game repositories.

## 15. Addition 2: jcodemunch-mcp (jgravelle)

- What: Python MCP server for symbol-level retrieval; sells itself on token savings. Licence: custom "dual-use": free for personal, academic, research and other non-commercial use; paid licence for commercial or for-profit use; redistribution restrictions including a ban on uploading derivatives to public registries (`LICENSE` lines 9-70, GitHub shows NOASSERTION). **Do not reuse code.**
- Design (README and `src/jcodemunch_mcp/`): tree-sitter indexing stores symbol metadata (signature, kind, qualified name, summary, byte offsets) beside raw files and retrieves exact byte ranges; 113 files under `tools/` implies about 100 tools (blast radius, dead code, call hierarchy, rename safety, PR risk, repo health, and more), which is a large tool surface. `get_repo_map(token_budget=2048)` is a query-less signature-level map packed greedily by file rank under a hard token cap (`tools/get_repo_map.py:1-23, 36-52, 161`). Safety tools return a `stop_rule.terminal` flag meaning "no further jcodemunch call will change this verdict", and refuse to turn missing evidence into a clean verdict: `check_rename_safe` answers `safe: null` when the import graph could not reach the symbol's file; `corpus_inadequate` and `dynamic_import_boundary` verdicts are never terminal (README line 152; `tools/_stop_rule.py`, `_corpus_adequacy.py`).
- Evidence (vendor): reproducible benchmark script on three public repos (express, fastapi, gin) reports 28.3x fewer tokens against a "grep-top-3" baseline and 241x against "read all" (`README.md` "Evidence", `TOKEN_SAVINGS.md`); per-query range 7.6x to 81.2x, and the README itself says to quote the range. A 50-iteration A/B test on a Vue 3 plus Firebase codebase with Sonnet 4.6 reports success 80 percent versus 72 percent, timeouts 32 versus 40 percent; the README labels it independent, but I could not verify that.
- Ideas (clean-room only): (a) `stop_rule`: tools state whether another call can change the answer; (b) three-valued results (`true`, `false`, `null` with reason) for absence claims, which prevents agents asserting "no references" when the index could not see; (c) a token-budget parameter on every list-returning tool. Effort S each.
- Fit: reject as a dependency or code source; reference_only for ideas.

## 18. Cluster summary

### Best practices the cluster converges on

1. Tree-sitter definition extraction with per-language query files is universal (aider, repomix, codanna, cgr, cbm, continue, roo, claude-context). The same C/C++ query (struct, union, function declarator, qualified method, typedef, enum, class) appears in aider and repomix verbatim.
2. A two-layer symbol model: syntactic definitions everywhere, with resolution layered above only where cheap (import-aware or type-aware). Name-only reference matching is the fallback (aider's Pygments backfill; cgr `heuristic` label; cbm `USAGE` edge when no unique callable target is proven).
3. Query-conditioned ranking by weighted reference graph with sqrt damping and penalties for private, generic and test names (aider, copied by cbm `pass_importance.c`). PageRank is used by aider only; cbm tried to skip it.
4. Budget-fitted outputs: a repo map packed to a token cap (aider binary search; jcodemunch greedy pack; continue 50 percent of context), compact tabular wire formats (cbm `compact_out`, jcodemunch MUNCH), pagination parameters (`offset`/`limit`, `start_index`/`max_results`), and truncation of long lines or contents (aider 100 characters, claude-context 5,000 characters).
5. Retrieval is moving from "embed everything" to hybrid lexical plus dense with exact-symbol tools beside it (claude-context RRF, continue FTS plus embeddings plus rerank, cbm BM25 plus embeddings, codanna ngram names plus doc embeddings). Pure dense search (Roo) is the weakest design.
6. Incremental indexing by content hash (claude-context SHA-256 plus Merkle, continue content-addressed cacheKey, roo segment hashes, cgr hash cache plus parser fingerprint) with a polling or debounced watcher (codanna 500 ms, CGC 2 s, cbm adaptive 5-60 s). The more careful tools retry failed re-indexes instead of dropping them (cbm watcher commit-on-success).
7. Deterministic navigation tools beat LLM-in-the-loop graph queries for exact questions (cgr states this in tool descriptions; codanna and cbm have the same shape: find/resolve, callers, callees, impact).
8. Honest coverage reporting is rare but valued: cbm `check_index_coverage`, cgr `resolution` labels and exclusion-state tracking, jcodemunch tri-state `null` verdicts and `corpus_inadequate`.
9. Generated prose documentation (DeepWiki, RepoAgent) is expensive, has no measured agent benefit, and independent evidence suggests overviews do not help.

### Where the cluster fails the target use case

- Macro-heavy C/C++ (Unreal `UCLASS`/`UFUNCTION`/`GENERATED_BODY`, X-macros, include-injected code): every tool parses with plain tree-sitter and loses declarations; only cgr (libclang hybrid, preprocessor recovery) and cbm (custom C hybrid LSP) attempt more, and neither has published results on an engine-scale macro tree. CGC's own backlog lists missing macro-defined enum members and callback edges.
- Shaders (HLSL, GLSL) and CMake: no tool in the requested list; cbm lists grammars but does not benchmark them.
- Cross-repository references (engine API called from a game repo, shader called from C++, Lua called from C++ bindings): only cgr (workspaces) and cbm (`CROSS_*` edges) address multi-repo, and only for service-style links, not symbol-level engine-to-game links.
- Reading: most tools return snippets or maps but leave the agent to read files with its own tools, so one task costs many calls; none offers address-based multi-range reads in one call.
- Honest uncertainty: most return empty lists without saying whether the index could have seen the answer.
- Scale evidence: none on multi-million-line mixed-language game trees with independent measurement.
- Operational weight: graph databases, daemons, Docker, cloud embeddings, or installers that modify agent configs.

### What the vault must do to beat them for the target use case

1. **Make mapping a first-class, budgeted, one-call operation.** `workspace` should return, for 5-7 repositories at once, a token-budgeted map: per-repository summary (languages, size, entry points, build system from CMake or `.uproject`/`.csproj`/`Cargo.toml`), directory tree with per-directory token counts and classification (source, vendored, generated, shaders, assets), and an aider-style ranked signature map, all fitted by binary search to a caller-supplied token budget. Pre-compute PageRank at index time and personalise it at query time with the user's query terms.
2. **Return exact addresses everywhere.** Every hit, outline row, reference row and map line carries `doc_id#Lstart-Lend` so a follow-up `read` of several addresses in one call replaces the grep, open, scroll loop. Offer an `expand` option that returns the enclosing symbol, N lines of context, or the file's outline.
3. **Resolve with honesty.** Store definitions and references with a resolution class (`exact`, `import_resolved`, `name_match`, `lexical`) and return it. Where an answer is negative, include whether the language of the files searched had reference extraction at all (tri-state, with a reason). Show per-language coverage in `vault_info` (symbols extracted, references extracted, parse error rate, files skipped and why).
4. **Treat macros and the preprocessor as data, not noise.** Plan, in order: (a) record `#define`, `#include`, `#if` conditions and macro invocations as references so `UCLASS`, `UPROPERTY`, `UE_LOG` and X-macro names are findable and linkable to their definitions; (b) a configurable macro-annotation table (Unreal reflection macros, `DECLARE_*`) so a macro like `UCLASS(...) class FOO_API AMyActor : public AActor { GENERATED_BODY() }` is parsed as a class with an export macro; (c) the preprocessor-conditional recovery pass (blank unbalanced branches, re-parse, keep offsets); (d) optional libclang enrichment from `compile_commands.json` when available. Measure each against a labelled test set drawn from the owner's repositories.
5. **Index shaders, CMake, Lua, GDScript and C# properly.** Use tree-sitter grammars for HLSL, GLSL, CMake, Lua, GDScript, C#, Rust, C, C++ (all MIT-licensed grammars exist: tree-sitter-hlsl, tree-sitter-glsl, tree-sitter-cmake, tree-sitter-lua, tree-sitter-gdscript, tree-sitter-c-sharp, tree-sitter-cpp). Add cross-language link rules specific to engines: shader file names referenced from C++ strings or material files, Lua/GDScript calls into C++ bindings by registered name, CMake targets to source globs. This is where the vault can plainly beat every tool here.
6. **Keep sizes small by default.** Default response budgets with explicit `truncated: true` and a continuation address; long lines clipped like aider; optional compact tabular rows like cbm's format for lists with 20 or more rows; token counts in every response header.
7. **Keep the tool count low and the descriptions precise.** The nine planned tools are a good size (jcodemunch exposes about 100 and cgr 35, which strains model tool selection). Borrow codanna's "what this tool does NOT show" wording, cgr's "use this instead when you know the exact name", and Context7's "do not call more than N times" guidance.
8. **Measure against the competitors on the owner's own tasks.** Build a small evaluation set (for example 40 questions over 5-7 real engine and game repositories: find definition, find all overrides, trace a call across files, locate a shader's C++ binding, answer an architecture question), with ground truth from compiler tooling where possible. Compare tool calls, tokens and correctness for: grep and read only; the vault; codebase-memory-mcp (run it only in a sandbox after review); codanna. Include a no-summary versus generated-summary arm, because the AGENTS.md study predicts generated overviews will not help.
9. **Add anchored agent notes.** A `notes` capability with content-hash plus text-quote anchors and EXACT/STALE/MOVED/AMBIGUOUS/LOST grading lets agents record "why" findings that survive re-indexing. cgr is the only tool with this, and the vault, which stores source verbatim, is better placed than a graph DB to do it.
10. **Do the unglamorous parts correctly.** Classify rather than delete (section 16); content-address chunks so two engine versions share embeddings; make re-index failures retry rather than drop; expose an async index job with status polling; fingerprint the parser and rule set so a grammar upgrade invalidates stale index data; scan for secrets before indexing.
